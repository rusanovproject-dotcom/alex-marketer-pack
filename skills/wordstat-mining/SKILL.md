# Спрос — как эту работу ищут словами

Ты не гадаешь, какими словами люди ищут дело владельца, и не переносишь на него слова
из соседней ниши. Ты **спрашиваешь у Яндекса** и получаешь две вещи, которых нет ни в
одном интервью: живые формулировки задачи и **сколько людей их набирает в месяц**.

**Место в маршруте.** Слой такта 2 (спрос). Сегменты и их работы даёт
`skills/jtbd/SKILL.md`, голос живых людей — `skills/voice-of-market/SKILL.md`. Здесь третий
угол: как задача звучит в строке поиска. Три угла на один вопрос — совпали, значит
сегмент настоящий; разошлись, значит владелец и рынок называют работу по-разному, и это
находка, а не помеха.

**Чего этот скилл не делает.** Не собирает семантику под кабинет, не кластеризует, не
считает транзакционность запроса по выдаче — это работа Директолога, и она начинается
после решения «идём в поиск». Здесь спрос как **факт о рынке**, а не как заготовка кампании.

## Ключ: официальный API (Yandex Cloud)

Инструмент — `scripts/wordstat.sh` в папке агента, официальный Search API v2. Не парсер,
не серый доступ.

**Как получить ключ** (консоль Yandex Cloud периодически переименовывает пункты меню —
ориентируйся по смыслу, не по точному тексту):

1. Зайди в консоль облака (`console.cloud.yandex.ru` или актуальный домен — ищи в поиске
   «Yandex Cloud консоль»).
2. Создай или выбери каталог (folder). Скопируй `folder_id` — он в URL страницы каталога.
3. Раздел «Сервисные аккаунты» → создай сервисный аккаунт и назначь ему роль
   `search-api.webSearch.user` на нужный каталог.
4. У сервисного аккаунта выпусти **API-ключ** с областью действия
   `yc.search-api.execute`. IAM-токен тоже поддерживается API, но этот локальный скрипт
   ожидает API-ключ.
5. Убедись, что Search API подключён в этом каталоге — иногда сервис нужно активировать
   отдельно перед первым запросом.
6. Сохрани ключ и id каталога:

```bash
mkdir -p ~/.secrets
cat > ~/.secrets/wordstat.json <<'JSON'
{ "api_key": "<API-ключ сервисного аккаунта>", "folder_id": "<id каталога>" }
JSON
chmod 600 ~/.secrets/wordstat.json
```

Нет ключа или платного аккаунта в облаке — **не блокируй такт**, переходи к фолбэку ниже.

Официальный текущий контракт:

- пример REST GetTop и настройка доступа:
  https://aistudio.yandex.ru/docs/en/search-api/operations/wordstat-gettop.html
- REST reference GetTop:
  https://aistudio.yandex.ru/docs/en/search-api/api-ref/Wordstat/getTop.html

## Команды

```bash
scripts/wordstat.sh top "фраза" [N] [--region ID[,ID...]]   # частотность + похожие фразы
scripts/wordstat.sh regions "фраза" [--top N]               # где спрос по регионам
```

| Аргумент | Что | Дефолт |
|---|---|---|
| `top "фраза"` | частотность фразы + похожие запросы | — |
| `N` (позиционный) | сколько похожих фраз вернуть | 50 |
| `--region ID[,ID…]` | geoId, можно списком | **нет — считает по всей России** |
| `regions "фраза"` | разбивка спроса по регионам | — |
| `--top N` | сколько регионов показать | 15 |

### Главная ловушка — регион обязателен

Без `--region` API считает по всей России, и цифра завышена в разы. Живой пример: «кухни
на заказ» — **76094 по РФ, 9763 в Москве, 1090 в Новосибирске**. Ниша локальная (мастер,
студия, региональный бизнес) — федеральная цифра врёт про его рынок на порядок.

**Порядок:**

1. Регион известен из `PROJECT.md` — берёшь оттуда.
2. Не известен или под вопросом — сначала `regions "фраза"`: посмотри, где спрос вообще
   есть, оттуда бери geoId.
3. Только потом `top "фраза" --region <geoId>`.

Частые geoId — в шапке `scripts/wordstat.sh`. Города там нет — не гадай, гони `regions`.

## Что делаешь с результатом

Из `top`: `totalCount` — основная частотность заданной фразы за последние 30 дней в
выбранном регионе. `results[]` содержит запросы со всеми словами исходной фразы,
`associations[]` — похожие запросы. Не подменяй `totalCount` значением первой строки
`results[]`: официальный REST-контракт возвращает их раздельно. Скрипт завершает работу
с ошибкой на HTTP 401/403/5xx, невалидном JSON или отсутствии любого из трёх полей.

**Три вопроса к выдаче, в этом порядке:**

| # | Вопрос | Что ищешь |
|---|---|---|
| 1 | **Спрос вообще есть?** | суммарная частота ядра фраз в регионе. Десятки в месяц — рынок поиска для него не главный канал, и это надо сказать вслух, а не прятать |
| 2 | **Какими словами он называется?** | живые формулировки: как человек сам произносит свою задачу, а не как её называет владелец в прайсе |
| 3 | **Где расходится с владельцем?** | владелец говорит «комплексный аудит», люди ищут «почему нет заявок с сайта» — разрыв языка, самая ценная находка такта |

**Отбор фраз — не по частоте, а по узнаваемости.** Берёшь те, что звучат как речь клиента,
и **сверяешь с дословным банком** из `skills/voice-of-market/SKILL.md`: фраза из Wordstat
совпала по смыслу с тем, что реально говорил живой человек — сильный сигнал. Совпадений
нет вовсе — повод усомниться, что сегмент выбран верно.

**Вес знания** (закон B, как везде):

- 🟢 — цифра пришла из API с указанным регионом и датой запроса
- 🟡 — цифра снята руками с `wordstat.yandex.ru` (человек мог сбить регион) или регион
  взят допущением
- 🔴 — частотность по РФ применена к локальному бизнесу
- ⚪ — не проверял

## Фолбэк без ключа — ручной чек-лист

Ключа нет или не завёлся — **не изображай, что подключил API**. Говоришь прямо и ведёшь
владельца руками:

1. Открыть `wordstat.yandex.ru`, войти под своим Яндекс-аккаунтом.
2. Выставить **регион** в поле сверху — без этого шага цифры федеральные и завышенные,
   та же ловушка, что и в API.
3. Ввести маску запроса — ту же, которой он назвал бы услугу в объявлении.
4. Записать из **левой колонки** топ-20 фраз с частотностью каждой.
5. Заглянуть в **правую колонку** («похожие запросы») — это расширение вбок: соседние
   формулировки и подсказки, чего в нише ищут рядом.
6. Занести в `MARKET.md` по форме ниже, пометив вес 🟡.

Разница с API — только способ получения цифр. Требования к региону и формат записи те же.

## Выход — дописать `MARKET.md`

Пишешь в секцию **«Дословный язык рынка»** отдельной подсекцией. Секции не переименовываешь,
чужие блоки не переставляешь, дописываешь по правилу владельца файла.

```markdown
### Спрос по Wordstat — <регион>, geoId <id>, снято <YYYY-MM-DD>

| Фраза | Частота/мес | Вес | Совпадает с голосом рынка |
|---|---|---|---|
| подбор кухни на заказ | 1090 | 🟢 | да — `customers.md`, Марина, 12.07 |
| кухня не влезает в бюджет | 340 | 🟢 | да |
| кухня под ключ недорого | 210 | 🟢 | нет |

**Ядро спроса:** <суммарная частота ключевых фраз> в месяц по региону.
**Разрыв языка:** владелец называет это «<его слова>», люди ищут «<их слова>».
**Источник:** Yandex Search API v2, регион <id>, дата запроса.
```

**Регион в заголовке обязателен.** Цифра без региона — не цифра, а мусор, и следующий
такт не сможет ей доверять.

Плюс одна строка в `TRACK.md` при закрытии: что теперь известно про спрос и чего не было
раньше.

## Частые ошибки

| Что | Почему плохо |
|---|---|
| Взял частотность без `--region` | Цифра завышена в разы, все решения по важности фраз поедут |
| Слепо взял самую частотную фразу | Частая ≠ узнаваемая. Сверяй с голосом рынка: фраза должна звучать как речь клиента |
| Ключа нет — сказал «данных не будет» | Ручной фолбэк обязателен, а не опционален |
| Записал цифру без региона и даты | Через месяц никто не поймёт, откуда она и к чему относится |
| Смешал фразы из Wordstat с цитатами живых людей | Это сигналы разной силы, источник обязан быть виден |
| Пошёл кластеризовать и собирать минус-слова | Не твоя работа — это Директолог, после решения идти в поиск |
| Спрос низкий, а ты промолчал | Худшее здесь. «Ищут 40 раз в месяц» — это факт, который меняет канал, и владелец обязан его услышать |
