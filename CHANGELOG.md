## [3.0.0] — 2026-08-04 (major — пересборка агента)

Полная пересборка. Это не доработка версии 2, а другой агент: он перестал быть
интервьюером с опросником и стал навигатором, который сам идёт в мир за фактурой
и приходит с догадкой о бизнесе на подтверждение.

### Что нового

- **Семь тактов вместо одного пайплайна.** Физика бизнеса → деньги назад (обратная
  воронка от прибыли и предельный CPL) → спрос и сегменты → голос рынка → конкуренты
  и свободное место → обещание и продуктовая лестница → путь клиента с узким местом →
  гипотеза с критерием. Такт закрывается, только когда владелец принял его выход.
- **11 скиллов вместо 4:** `onboard`, `mkt-recon`, `jtbd`, `voice-of-market`, `rivals`,
  `core-offer`, `offer-lab`, `niche-scan`, `synthetic-custdev`, `funnel`, `growth-lab`.
- **Три сквозных закона:** не выдумывай (внешняя сверка с источником), помечай вес
  каждого утверждения (🟢 факт / 🟡 гипотеза / 🔴 синтетика / ⚪ белое пятно), ищи
  AI-рычаг с эффектом и сроком замера.
- **Критик-гейт A-F вслух с цитатами** на каждой отдаче, порог ≥ B. Флаг без цитаты
  не считается флагом.
- **Золотые файлы проекта** — `PROJECT.md` (паспорт), `MARKET.md` (что найдено в нише
  со ссылками), `TRACK.md` (журнал рубежей и решений) вместо разрозненных артефактов.
- **Кастдев без живых клиентов** (`synthetic-custdev`) — пять синтетических персон,
  весь производный выход честно помечен 🔴 и произносится вслух первой фразой.
- **Затравка памяти:** `memory.md`, `failures.md`, `wins.md` приходят не пустыми, а с
  обезличенными уроками из практики.

### ⚠️ Ломающие изменения

- **Агент сменил имя папки:** `office/agents/alex-marketer/` → `office/agents/marketer/`.
  Ставить новую версию поверх старой нельзя — в офисе окажутся два маркетолога,
  оба откликаются на «алекс» и «маркетолог». Порядок перехода без потери наработок —
  в README, раздел «Если у тебя уже стоял Алекс прежней версии».
- **Скиллы больше не ставятся в `.claude/skills/`.** Они живут бандлом внутри папки
  агента (`skills/`), агент вызывает их сам чтением файла. Разложишь по `.claude/skills/` —
  вся таблица роутинга агента укажет в пустоту.
- **Убран `scripts/update-pack.sh`.** Он писан под прежнюю структуру (глобальные скиллы
  плюс `manifest.yaml`) и на новой ломает установку. Обновление теперь простое:
  склонировать репо заново и перекопировать папку целиком, сохранив свои `overrides.md`,
  `memory.md`, `failures.md`, `wins.md` и `agent-state.md`.
- **Убран `manifest.yaml`** — метаданные установки теперь в `install.md`.
- **Скиллы `jtbd-critic` и `marketer-log-deal` убраны как отдельные.** Работа критика
  вшита в каждый скилл гейтом A-F; запись клиентской встречи переехала в
  `voice-of-market`. Старые имена команд разведены алиасами в `CLAUDE.md` — привычные
  обращения продолжают попадать куда нужно.
- **Убрано расширение `extensions/sales-meetings`.** Карточки клиентов ведёт
  `voice-of-market` по шаблону `templates/customers.template.md`.
- **Глобальный скилл `custdev` больше не требуется** — его роль закрывает локальный
  `synthetic-custdev`. Если он остался у тебя от прежней версии, удалять не обязательно,
  он просто не нужен этому агенту.

## [2.1.1] — 2026-05-12 (patch)

### Архитектурный фикс — поиск глобальных скиллов

В v2.1.0 `scripts/verify-pack.sh` искал `.claude/skills/<name>/` только относительно корня пака. Но у ученика после установки глобальные скиллы живут в **корне workspace** (`workspace/.claude/skills/`), а Алекс — в `office/agents/alex-marketer/`. Verify падал хотя custdev был на месте.

### Исправлено

- `scripts/verify-pack.sh` теперь ищет глобальные скиллы по 3 локациям в порядке приоритета:
  1. Внутри пака (`$PACK_ROOT/.claude/skills/<name>/`) — для свежего клона репо
  2. Подъём по дереву до первой родительской папки с `.claude/skills/<name>/` — для установленного workspace
  3. `$HOME/.claude/skills/<name>/` — системные скиллы Claude Code
- `scripts/update-pack.sh` теперь кладёт глобальные скиллы в **корень workspace**, а не внутрь пака. Корень определяется подъёмом по дереву до папки с `.claude/` или `office/`.

### Документация

- Архитектурное решение про разделение local/global скиллов задокументировано в `SPEC-v2.1.md`.

## [2.1.0] — 2026-05-12

### 🔴 Критический фикс зависимостей

В v2.0 пак ссылался на `/custdev` как **обязательный путь** при `has_paying_customers: false`, но сам скилл физически отсутствовал в репозитории. Ученики упирались в тупик.

### Добавлено

- **`/custdev` теперь в паке** — `.claude/skills/custdev/SKILL.md`. Глобальный скилл, доступен как slash-команда во всём workspace после установки.
- **`/core-offer` v0.2** — `skills/core-offer/`. Stage 0-7 полный пайплайн упаковки центральной фразы: щёлк → направление vs продукт → 4 раунда штурма (Reason to Want) → объединённый раунд доказательств (Reason to Believe) → было/стало → 3 формы оффера.
- **`manifest.yaml`** — декларативное описание зависимостей пака (local_skills, global_skills, preserved_user_files, known_gaps).
- **`scripts/verify-pack.sh`** — проверка целостности перед публикацией. Грепает все `/skill-name` ссылки в `*.md` и сверяет с manifest. Запускается мейнтейнером.
- **`scripts/update-pack.sh`** — апдейт пака у ученика. Скачивает свежую версию, делает diff, бэкап, применяет с сохранением клиентских данных (overrides.md, projects/, customers/, etc).
- **`.alex-pack-baseline/`** — папка с эталонными версиями core.md/soul.md от последнего апдейта. Используется чтобы заметить если ученик правил core.md руками.
- **`CHANGELOG.md`** — этот файл.
- **`SPEC-v2.1.md`** — лог архитектурных решений.

### Изменено

- **`core.md` синхронизирован с актуальным workspace** — Stage 2 переведена из «не подключена» в «закрыта через `/core-offer`». Pipeline расширен, обновлены триггеры маршрутизации и Stage Lock. Связки с Producer/Copywriter/Designer обновлены под новый `core-offer.md`.
- **README.md** — добавлена секция «Обновление пака» с командой `bash scripts/update-pack.sh`.

### Известные дыры (не блокирующие)

- **`/marketer-enable-meetings`** — упомянут в `core.md`, `install.md`, `README.md`, `extensions/sales-meetings/CUSTOMER-INTELLIGENCE.md` как активатор опционального модуля Customer Intelligence. Физически скилл не реализован. Записан в `manifest.yaml` → `known_gaps:`. В следующей версии — либо реализуем, либо вычищаем упоминания.

### Миграция с v2.0 → v2.1

> ⚠️ **Инструкции ниже устарели с версии 3.0.0.** `scripts/update-pack.sh` в паке больше нет,
> команда `curl` на него вернёт 404. Переход на версию 3 описан в README, раздел
> «Если у тебя уже стоял Алекс прежней версии». Текст оставлен как история версий.

**Если у тебя пак v2.0 уже установлен:**

```bash
cd ~/path/to/your/office/agents/alex-marketer
bash scripts/update-pack.sh
```

Если `scripts/update-pack.sh` не у тебя локально (это новый файл в v2.1) — скачай и запусти:

```bash
curl -fsSL https://raw.githubusercontent.com/rusanovproject-dotcom/alex-marketer-pack/main/scripts/update-pack.sh -o /tmp/update-pack.sh
bash /tmp/update-pack.sh ~/path/to/your/office/agents/alex-marketer
```

Скрипт:
- Скачает свежий пак, сравнит с твоим
- Покажет что изменится
- Создаст бэкап старой версии в `.alex-pack-backups/`
- Применит апдейт, **сохранив**: `overrides.md`, `agent-state.md`, `memory.md`, `failures.md`, `projects/`, `customers/`, `inbox/`
