# alex-marketer-pack v2.1 — Spec

> Документ для истории и следующих версий. Лог архитектурных решений по системе апдейтов.

## Что чиним

В v2.0 публичный пак имеет дыры зависимостей:
- `/custdev` упомянут как «единственный путь» при zero-data, **физически отсутствует** в паке. Ученик упирается в тупик.
- `/marketer-enable-meetings` упомянут в core.md / install.md / README, **физически отсутствует** во всей системе (упомянутый, но не реализованный).
- `/core-offer` (упаковщик центральной фразы, Stage 2) есть в workspace v0.2 с 1 мая, **не довезён в публичный пак**.
- `core.md` отстал от workspace на 2 недели — расхождение MD5.

Корень — при упаковке v2.0 не проверили все ссылки на скиллы в `*.md` файлах против физического наличия.

## Архитектура решения — 3 слоя

### Слой 1 — `manifest.yaml`

В корне пака. Описывает что в паке, что зависит от чего, какие файлы НЕ перезаписывать при апдейте.

Парсится bash-скриптами через `grep + sed` без зависимостей (`yq` / `python` не нужны — у ученика может не быть).

### Слой 2 — `scripts/verify-pack.sh`

Запускается **перед каждой публикацией**. Делает:
1. Парсит manifest.yaml
2. Грепает все `/<skill-name>` ссылки в `*.md` файлах пака
3. Сверяет с manifest и физическим наличием
4. Fail если ссылка ведёт в никуда
5. Игнор-лист для технических команд (`/accept`, `/clear`, `/compact`)

### Слой 3 — `scripts/update-pack.sh`

Запускается **у ученика** одной командой. Делает:
1. Скачивает свежий пак из GitHub (depth 1, минимум данных)
2. Сравнивает версии (manifest.yaml)
3. Показывает diff
4. Спрашивает подтверждение
5. **Создаёт бэкап** старой версии (timestamped)
6. Применяет rsync с исключением `preserved_user_files`
7. Копирует `global_skills` в `.claude/skills/` ученика
8. Запускает `verify-pack.sh` локально для проверки целостности

## Preserved user files — что НЕ перезаписывается

- `overrides.md` — клиентские правила (мат, ниша, запреты)
- `agent-state.md` — состояние работы (interrupted, current_skill)
- `memory.md` — память агента (Decisions / Patterns / Context)
- `failures.md` — лог фейлов агента
- `projects/` — клиентские проекты (фактура, аналитика)
- `customers/` — клиентская база
- `inbox/` — входящие задачи ученика

## Pre-mortem — что может сломаться

1. **Ученик правил core.md руками** → апдейт затрёт. Mitigation: `update-pack.sh` делает diff на core.md, если отличается от старой версии репо — предупреждает «перенеси в overrides.md».
2. **Ученик удалил скилл специально** → апдейт его вернёт. Mitigation: в `overrides.md` поле `disabled_global_skills:` — апдейт это уважает.
3. **GitHub блок в России** → апдейт падает. Mitigation: альтернативный канал (zip-архив через прямой curl). Пометить в README.
4. **Скилл переименован** → старая ссылка битая. Mitigation: в manifest секция `renames:` со старыми → новыми именами.
5. **Зависимости от внешних утилит** → ученик не может запустить скрипт. Mitigation: чистый bash без `yq`/`python`/`jq`. Только базовые `grep`/`sed`/`rsync`/`curl`/`git`.
